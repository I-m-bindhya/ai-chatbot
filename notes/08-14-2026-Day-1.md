# 1. JavaScript Fundamentals

## 1.1 `var`, `let`, `const`

- `var` → function scoped
- `let` / `const` → block scoped
- `let` and `const` have a Temporal Dead Zone (TDZ)
- `const` prevents reassignment of the variable binding, but objects/arrays can still be mutated.

---

## 1.2 Lexical Scope

Lexical scope means a function can access variables based on **where the function was defined**, not where it is called.

```javascript
let name = "outer";

function outer() {
    let name = "inner";

    function inner() {
        console.log(name);
    }

    inner();
}

inner() accesses the name from its surrounding lexical environment.

Interview Definition

Lexical scope determines variable accessibility based on the physical location where a function is defined in the source code.

2. Hoisting

JavaScript processes declarations during environment setup before executing the code.

var
console.log(a);

var a = 10;

Output:

undefined

Conceptually:

var a;
console.log(a);

a = 10;

The declaration is hoisted, but initialization happens later.

let / const
console.log(a);

let a = 10;

Result:

ReferenceError

The variable exists in the environment but cannot be accessed before its declaration is executed.

This period is called the:

Temporal Dead Zone (TDZ)

3. Closures

A closure occurs when a function remembers and can access variables from its outer lexical environment even after the outer function has finished execution.

function counter() {
    let count = 0;

    return function () {
        count++;
        return count;
    };
}
const counter1 = counter();

counter1(); // 1
counter1(); // 2
counter1(); // 3

Creating another counter:

const counter2 = counter();

creates a new closure/environment.

Therefore:

counter1 → 1 → 2 → 3

counter2 → 1
Key Interview Concept

Each call to the outer function creates a separate lexical environment.

4. this

For a normal function:

this is determined by how the function is called.

Example:

    name: "Bindhya",

Here:

this → user

Output:

    name: "AI Engineer",
    greet: user.greet

anotherUser.greet();

Here:

this → anotherUser

because the function is called as:

The function does not permanently belong to user.

Arrow functions do not have their own this.

They capture this from their surrounding lexical environment.

8. Shallow Copy vs Deep Copy
Reference Assignment
const user2 = user1;

Both variables point to the same object.

Shallow Copy
const user2 = { ...user1 };

Creates a new top-level object.

However, nested objects remain shared.

Example:

const user1 = {
    name: "Bindhya",
    address: {
        city: "Chennai"
    }
};

const user2 = { ...user1 };

Conceptually:

user1 ───────┐
             ├──→ address object
user2 ───────┘

Therefore:

user2.address.city = "Bangalore";

also changes:

user1.address.city;
Deep Copy
const user2 = structuredClone(user1);

Nested objects are independently copied.

Key Rule
Primitive
   ↓
Value copied

Object / Array
   ↓
Reference copied

13. Two Sum
Brute Force
const numbers = [2, 7, 2, 15];
const target = 9;

let answer;

for (let i = 0; i < numbers.length; i++) {
    for (let j = i + 1; j < numbers.length; j++) {
        if (numbers[i] + numbers[j] === target) {
            answer = [i, j];
            break;
        }
    }
}

console.log(answer);

Complexity:

Time  → O(n²)
Space → O(1)
Optimized Two Sum — Map

Core idea:

complement = target - current

Use a Map to remember previously seen values.

function twoSum(numbers, target) {
    const seen = new Map();

    for (let i = 0; i < numbers.length; i++) {
        const complement = target - numbers[i];

        if (seen.has(complement)) {
            return [seen.get(complement), i];
        }

        seen.set(numbers[i], i);
    }

    return [];
}

Example:

console.log(twoSum([2, 7, 8, 15], 23));

Output:

[2, 3]

Because:

8 + 15 = 23
Complexity
Time  → O(n)
Space → O(n)
Interview Explanation

For every number, I calculate its complement using target - current. I check whether that complement already exists in the Map. If it exists, I found the required pair. Otherwise, I store the current number and its index.

Important Concept

We trade memory for faster lookup.

Array → includes() → O(n)

Map → has() → O(1) average
14. Valid Anagram

An anagram requires frequency counting.

Example:

const s = "listen";
const t = "silent";

Both contain the same characters with the same frequencies.

Frequency Map
const seen = new Map();

for (let i = 0; i < s.length; i++) {
    seen.set(
        s[i],
        (seen.get(s[i]) || 0) + 1
    );
}

For:

"aab"

Map becomes:

a → 2
b → 1

Then process the second string and decrement the frequencies.

seen.set(
    t[i],
    seen.get(t[i]) - 1
);
Important JavaScript Correction

Avoid:

if (!seen.get(s[i]) == 0)

Use:

if (seen.get(s[i]) !== 0)
Complexity
Time  → O(n)
Space → O(k)

Where k is the number of distinct characters.

For a fixed character set, auxiliary space can effectively be considered O(1).

15. Longest Substring Without Repeating Characters

This problem introduced the:

Sliding Window Pattern

Given:

const s = "abcabcbb";

Answer:

3

because:

"abc"

is the longest substring without repeating characters.

Important Concept — Substring

A substring must be continuous.

For:

"abcabcbb"

"abc" is a substring.

"ac" is not a substring because b was skipped.

16. Sliding Window

Maintain two pointers:

left
right

Conceptually:

left
 ↓
a b c a b c b b
      ↑
     right

When a duplicate appears:

duplicate found
       ↓
move left forward
       ↓
remove characters
       ↓
window becomes valid
Our Solution
var lengthOfLongestSubstring = function(s) {

    let left = 0;
    let maxLength = 0;
    let seen = new Set();

    for (let right = 0; right < s.length; right++) {

        while (seen.has(s[right])) {
            seen.delete(s[left]);
            left++;
        }

        seen.add(s[right]);

        maxLength = Math.max(
            maxLength,
            right - left + 1
        );
    }

    return maxLength;
};
Why while instead of if?

A duplicate may require moving left more than once.

Example:

"cbb"

When the second b is encountered:

c b b

Moving left once may still leave:

b b

which is invalid.

Therefore:

while (seen.has(s[right]))

continues until the duplicate is removed.

Window Length
right - left + 1

Example:

left  = 2
right = 4

length = 4 - 2 + 1
       = 3
Complexity
Time  → O(n)
Space → O(k)

Why is the time O(n) even though there is a while loop inside the for loop?

Because both pointers only move forward.

right → at most n movements
left  → at most n movements

Therefore:

O(n) + O(n)
= O(2n)
= O(n)
Reusable Pattern
Sliding Window
      +
Two Pointers
      +
Set / Map
      ↓
Efficient window processing
